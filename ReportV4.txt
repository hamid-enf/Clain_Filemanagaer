3. Critical Findings (CRIT-01 – CRIT-05)
[CRIT-01] UsbMsc_StorageWrite / UsbMsc_StorageRead Unchecked blk_len Global Bounce-Buffer Overflow

    Severity: Critical (Out-of-bounds .bss write up to 32,256 bytes in priority-0 USB ISR)
    File & Lines: FileManager_lib/top_api/usb_msc.h:143, 421–435, 449–463
    Root Cause:
    g_usb_msc_bounce is a static 4096-byte (8-sector) DMA bounce buffer (top_api/usb_msc.h:143):

    C

    static FM_DMA_ALIGNED uint8_t g_usb_msc_bounce[4096];

    In
    UsbMsc_StorageWrite (lines 449–463), total = (uint32_t)blk_len * 512u; is computed from uint16_t blk_len without bounds checking against sizeof(g_usb_msc_bounce):

    C

    if (!FM_Cache_SdDirectOk(buf, total)) {
        memcpy(g_usb_msc_bounce, buf, total); /* OVERFLOWS WHEN blk_len > 8! */

    When USB MSC
    MSC_MEDIA_PACKET is configured to 8192..32768 bytes (blk_len = 16..64) and the USB stack passes an unaligned buffer, memcpy overwrites up to 28 KB+ of adjacent .bss globals from inside OTG_FS_IRQHandler. (Compare USB_DEVICE/App/usbd_storage_if.c:218–260, which loops 1 sector at a time.)
    Dynamic Proof (/tmp/harnesses/repro_suite1 [10]):
        Compile-time warning: warning: '__builtin_memcpy' writing 8192 bytes into a region of size 4096 overflows the destination [-Wstringop-overflow=].
        Runtime ASan crash on UsbMsc_StorageWrite(0, pkt, 0, 16): AddressSanitizer: global-buffer-overflow WRITE of size 8192 (exitcode = 88).
    Fix: Loop over blk_len in chunks of at most sizeof(g_usb_msc_bounce) / 512u (8 sectors) in both UsbMsc_StorageRead and UsbMsc_StorageWrite.

[CRIT-02] LittleFS_Init Permanent g_lfs[] Slot Leak + FS_Mount Zero-ops Acceptance -> NULL Function-Pointer Call (pc = 0x0)

    Severity: Critical (Permanent resource exhaustion across Deinit/Init + NULL function pointer jump)
    File & Lines: FileManager_lib/backends/fm_littlefs.c:1004–1036, FileManager_lib/src/fm_filesystem.c:480–565, FileManager_lib/src/fm_file.c:1009
    Root Cause:
        LittleFS_Init(FM_FS *fs) claims a slot in static LFS_Ctx g_lfs[FM_MAX_FS] (4 slots) keyed by g_lfs[i].owner = fs. Unlike FatFS_Init (backends/fm_fatfs.c:760–815, which clears ctx->owner = NULL on mount failure and unmount), fm_littlefs.c never clears g_lfs[i].owner in lfs_fs_mount error paths, lfs_fs_unmount, or FileManager_Deinit(). Four failed mount attempts with stack-allocated FM_FS structs permanently exhaust all g_lfs[] slots until MCU reset.
        On the 5th call, LittleFS_Init(&fs) executes memset(fs, 0, sizeof(*fs)); (line 1007) and returns FM_ERR_NO_MEMORY. Because FS_Mount(mount_path, fs) (src/fm_filesystem.c:525) treats fs->ops.mount == NULL as "no mount callback needed" instead of rejecting an uninitialized FM_FS (fs->ops.file_open == NULL), FS_Mount succeeds with FM_OK (0)! Any subsequent File_Open executes mount->fs->ops.file_open(...) (src/fm_file.c:1009) without a NULL check, jumping to 0x00000000.
    Dynamic Proof (/tmp/harnesses/repro_suite1 [12]):

    text

    5th LittleFS_Init r=-14 (NO_MEMORY), FS_Mount r=0 (MOUNTED ZERO-OPS FS!)
    AddressSanitizer: SEGV on unknown address 0x000000000000 (pc 0x000000000000)
    Child File_Open on zero-ops mount -> exited=1 code=88

    Fix: (1) Release ctx->owner = NULL on lfs_fs_mount failure and lfs_fs_unmount (matching fm_fatfs.c); (2) in FS_Mount, reject any FM_FS missing mandatory ops (ops.mount == NULL || ops.file_open == NULL || ops.file_close == NULL || ops.stat == NULL) with FM_ERR_INVALID_ARGUMENT.

[CRIT-03] Text_Replace, Text_InsertLine, and Text_DeleteLine .fm_tmp Truncation Deletes Source File or Sibling .fm* Files

    Severity: Critical (Silent destruction of user source file or unrelated sibling file)
    File & Lines: FileManager_lib/src/fm_text.c:259, 387, 486, 544–547
    Root Cause:
    All three mutating text helpers build char tmp_path[FM_PATH_MAX] (160 bytes) via unchecked snprintf:

    C

    (void)snprintf(tmp_path, sizeof(tmp_path), "%s.fm_tmp", path);

        When strlen(path) == 159 (a completely valid path < FM_PATH_MAX), tmp_path truncates to path itself. Opening out on tmp_path fails with FM_ERR_BUSY because in is open on path; cleanup closes in and executes (void)File_Delete(tmp_path); (line 546), deleting the user's original file!
        When strlen(path) is 153..158, tmp_path collides with <path>.f, <path>.fm, <path>.fm_, <path>.fm_t, or <path>.fm_tm, overwriting and then deleting/renaming an unrelated sibling file while returning FM_OK (0)!
    Dynamic Proof (/tmp/harnesses/repro_suite1 [1]):
        159-char path: File_WriteAll=0 -> Text_DeleteLine=-3 -> source file exists=0 (USER FILE DELETED!)
        156-char path: Text_Replace=0 -> sibling .fm exists=0 (UNRELATED SIBLING DELETED!)
    Fix: Validate size_t len = strlen(path); if (len + sizeof(".fm_tmp") > sizeof(tmp_path)) return FM_ERR_TOO_LARGE; (matching src/fm_safe.c) before opening any file.

[CRIT-04] FM_Qspi_WaitReady Soft-Reset Drops 4-Byte Addressing Mode (>=32 MiB) + qspi_erase_sector Accepts Aborted Half-Erased Sectors

    Severity: Critical (Silent flash corruption across low 16 MiB & half-erased NOR sectors)
    File & Lines: FileManager_lib/src/fm_qspi.c:199–204, 300–310, 577–618, 757–772
    Root Cause:
        On > 16 MiB NOR chips (W25Q256/W25Q512), FM_Qspi_Init enters 4-byte addressing via 0xB7 (QCMD_ENTER_4BYTE_ADDR) once at init and uses 3-byte opcodes (0x03, 0x02, 0x20) with addr_bytes = 4. On any FM_Qspi_WaitReady timeout (lines 201–202), the driver sends 0x66 + 0x99 (Reset Enable + Reset), which resets the flash IC to 3-byte addressing mode without re-sending 0xB7. Subsequent retries and future I/O send 4-byte addresses to a chip in 3-byte mode: 0x20 erases (addr >> 8) in the low 16 MiB, and 0x02 programs addr & 0xFF as the 1st data byte at (addr >> 8), returning FM_OK!
        In qspi_erase_sector (lines 595–608), after FM_Qspi_WaitReady aborts a slow erase via 0x66/0x99 soft-reset, the polling loop sees SR1.BUSY == 0 (caused by the reset itself!), logs "the sector may be half erased", and returns FM_OK without re-erasing the sector.
    Dynamic Proof (/tmp/harnesses/repro_suite1 [11]):

    text

    Erase @0x01000000 after 1 timeout: r=0, addr_mode_4b=0,
    mem[0x01000000]=0xAA (UNERASED!), mem[0x00010000]=0xFF (CORRUPTED LOW 16MB!)

    Fix: Either use dedicated 4-byte opcodes (0x13 Read4B, 0x12 PageProgram4B, 0x21 SectorErase4B — stateless across resets!) or re-issue QCMD_ENTER_4BYTE_ADDR inside FM_Qspi_WaitReady after QCMD_RESET; and in qspi_erase_sector, never return FM_OK after a soft-reset without re-issuing QCMD_SECTOR_ERASE_4K.

[CRIT-05] FM_Qspi_Write Read-Modify-Erase-Write Breaks LittleFS Crash Atomicity (and Fails Outright When sector_buf == NULL)

    Severity: Critical (Complete loss of already-committed LittleFS files on brownout; FM_ERR_IO mount failure without sector_buf)
    File & Lines: FileManager_lib/src/fm_qspi.c:802–868, 925–955, FileManager_lib/backends/fm_littlefs.c:120–175
    Root Cause:
    FM_Qspi_RegisterStorage exposes write_size = 256 and erase_size = 4096, so LittleFS erases 4 KB blocks via ops.erase and appends 256-byte pages (len = 256) via ops.write. However, FM_Qspi_Write (line 814) only programs directly when (addr % 4096 == 0) && (len % 4096 == 0):
        With sector_buf == NULL, every 256-byte LittleFS write fails with FM_ERR_UNSUPPORTED -> FS_Mount fails (-6 FM_ERR_IO).
        With sector_buf != NULL, every 256-byte LittleFS metadata commit reads, erases (qspi_erase_sector), and rewrites the entire 4 KB active metadata block, causing up to 16x NOR erase wear amplification and wiping previously committed metadata tags in that block if power fails during the erase.
    Dynamic Proof (/tmp/harnesses/repro_qspi_powercut):

    text

    [QSPI-LFS-1] LittleFS on FM_Qspi(sector_buf=NULL): FS_Mount=-6
    [!] LittleFS on FM_Qspi power-cut at erase 1/2 DESTROYED committed /q1/first.txt! (mount=0 read=-3)
    [!] LittleFS on FM_Qspi power-cut at erase 2/2 DESTROYED committed /q1/first.txt! (mount=0 read=-3)
    [QSPI-FMFS] FMFS v2 + File_Transaction + FMFS_Repack across 140 power-cut erases: lost=0

    Fix: In FM_Qspi_Write (or a dedicated raw page-program path / blank-check fast path), read the target range [addr, addr + len) (or check (existing[i] & ~src[i]) / existing[i] == 0xFF): when all target bytes on flash already satisfy (existing[i] & src[i]) == src[i] (as is always true for LittleFS page appends into an erased block!), call qspi_write_erased(dev, addr, src, len) directly without sector_buf or qspi_erase_sector!

4. High-Severity Findings (HIGH-01 – HIGH-08)
[HIGH-01] fatfs_get_type 2-Byte Buffer Overflow (backends/fm_fatfs.c:734–752)

    Root Cause: Validates type_size < sizeof("FAT") (4), then strcpys "FAT12" / "FAT16" / "FAT32" / "exFAT" (6 bytes) into type.
    Dynamic Proof (repro_real_fatfs2): AddressSanitizer: heap-buffer-overflow WRITE of size 6 on fatfs.ops.get_type(&fatfs, malloc(4), 4) (exitcode = 88).
    Fix: Check the exact string length size_t need = strlen(s) + 1; if (type_size < need) return FM_ERR_TOO_LARGE; memcpy(type, s, need);.

[HIGH-02] Shipped FATFS/Target/ffconf.h (_FS_LOCK = 2) Breaks Directory_Copy on Any Non-Empty Directory and Caps Concurrent Opens at 2

    File & Lines: FATFS/Target/ffconf.h:230 (#define _FS_LOCK 2), backends/fm_fatfs.c:415–465, 635–660
    Root Cause: Real FatFS shares Files[_FS_LOCK] across all open FIL and DIR objects (ff.c:inc_lock). Directory_Copy holds 1 DIR lock while File_Copy opens src (lock #2) + dst (lock #3 > _FS_LOCK), failing 100% of the time with FR_TOO_MANY_OPEN_FILES -> FM_ERR_NO_MEMORY (-14) even when 0 other files are open! test/fatfs_mock/ff_mock.c does not model _FS_LOCK, hiding this target-breaking mismatch.
    Dynamic Proof (repro_real_fatfs [FatFS-B]): On real ff.c R0.12c + shipped ffconf.h, 3rd File_Open(READ) -> NULL (err = -14); Directory_Copy("/fat/src_dir" [1 file], "/fat/dst_dir") with 0 open files -> -14 (FM_ERR_NO_MEMORY).
    Fix: Set #define _FS_LOCK (FM_MAX_OPEN_FILES + FM_MAX_OPEN_DIRS) (at least 12..16) in FATFS/Target/ffconf.h, add a #if defined(_FS_LOCK) && _FS_LOCK > 0 && _FS_LOCK < (FM_MAX_OPEN_FILES + FM_MAX_OPEN_DIRS) compile-time #warning/#error in backends/fm_fatfs.c, and model _FS_LOCK in ff_mock.c.

[HIGH-03] Storage_Format and Storage_Unmount Bypass VFS Mount & Open-File Checks (src/fm_storage.c:402–460)

    Root Cause: Unlike FS_Format and Storage_Unregister, neither Storage_Format nor Storage_Unmount checks whether a VFS filesystem in g_mounts[] is currently mounted on s (or has open files/directories). Storage_Format("live") erases all sectors of a live mounted filesystem to 0xFF under active open writers and returns FM_OK.
    Dynamic Proof (repro_suite1b): With /live mounted and an active FM_OPEN_WRITE handle: FS_Format = -8 (BUSY), Storage_Unregister = -8 (BUSY), Storage_Format = 0 ("FMFS" superblock wiped to FF FF FF FF), Storage_Unmount = 0.
    Fix: Expose FM_Bool FM_VFS_IsStorageInUse(const FM_Storage *s) from fm_filesystem.c and reject public Storage_Format / Storage_Unmount calls with FM_ERR_BUSY when a VFS mount still references s.

[HIGH-04] LittleFS FS_Format Corrupts Mounted lfs_t State + LittleFS_SetAutoFormat(FM_FALSE) Catch-22 + RamDisk_Register SIGABRT

    File & Lines: backends/fm_littlefs.c:120–160, 347–420, 910–940, backends/fm_ramdisk.c:167
    Root Cause:
        lfs_fs_format calls lfs_format(&ctx->lfs, &ctx->cfg) without lfs_unmount before and lfs_mount after, leaving ctx->lfs out of sync with flash so every subsequent operation returns FM_ERR_CORRUPTED (-12).
        When LittleFS_SetAutoFormat(&fs, FM_FALSE) is used on blank/corrupted flash, FS_Mount fails and leaves /lfs unmounted, so FS_Format("/lfs") returns FM_ERR_NOT_MOUNTED, and there is no LittleFS_FormatStorage API.
        RamDisk_Register sets erase_size = 1 (block_size = 1), while lfs_setup_cfg bumps read_size/prog_size/cache_size to 16 without ensuring block_size >= 128 and block_size % prog_size == 0, triggering LFS_ASSERT (SIGABRT).
    Dynamic Proof (repro_suite1 [2]): FS_Format("/lfs") = 0 -> File_WriteAll = -12, Directory_Create = -12; RamDisk_Register + LittleFS FS_Mount -> SIGABRT (sig = 6).
    Fix: In lfs_fs_format, lfs_unmount -> lfs_format -> lfs_mount; add LittleFS_FormatStorage(FM_Storage *s); validate block_size >= cache_size && (block_size % prog_size) == 0 && block_count >= 2 in lfs_setup_cfg before calling lfs.c.

[HIGH-05] Directory_Rename Bypasses Open-File Busy Check, Item-Type Check, Parent-Into-Child Cycle Check, and Cache Invalidation (src/fm_directory.c:309–349)

    Root Cause: Calls ops.rename directly without ops.stat (FM_ITEM_DIR), FM_File_OpenOnPath / open-descendant check, dir_relation cycle check, or FM_File_InvalidateMount.
    Dynamic Proof (repro_suite1 [4]):
        Open regular file: File_Rename = -8 (BUSY) vs Directory_Rename = 0 (RENAMED OPEN FILE!).
        Cycle move: Directory_Move("/lfs/p", "/lfs/p/child") = -1 vs Directory_Rename("/lfs/p", "/lfs/p/child") = 0 (orphaned cycle on LittleFS!).
    Fix: Verify src is FM_ITEM_DIR, reject dir_relation(src_rel, dst_rel) != DIR_UNRELATED, reject any open file or open FM_Dir under src_rel or dst_rel, and call FM_File_InvalidateMount(src_mount).

[HIGH-06] Logger_Write & JsonWriter_Float NaN/Inf Undefined Behavior + Fabricated Finite Telemetry + JsonWriter_Float 2^32 Wrap

    File & Lines: src/fm_logger.c:105–155, 735–785, src/fm_json.c:1756–1812
    Root Cause:
        Neither formatter checks isnan(v) / isinf(v). Casting NAN to int64_t is UB (C99 §6.3.1.4) and produces negative scaled = INT64_MIN on x86-64, which wraps via (uint32_t) casts into valid-looking finite numbers (1511828489.4294966488 for NAN, 9000000.000 for INFINITY) in CSV/JSONL sensor logs!
        JsonWriter_Float clamps value to 9000000000.0f (9e9), then formats ip with u32_to_str((uint32_t)ip, int_s) (line 1796) instead of u64_to_str, wrapping every float >= 4,294,967,296 modulo 2^32!
    Dynamic Proof (repro_suite1b & repro_powercut_fuzz):
        Logger_Write JSONL: {"ts":1000,"seq":0,"v":[1511828489.4294966488,9000000.000]}
        JsonWriter_Float: {"five_billion":705032704.0,"pos_inf":410064896.0,"nan_val":1511828489.4294966488}
    Fix: Check isnan(v) || isinf(v) up front (return FM_ERR_INVALID_ARGUMENT or emit JSON null / CSV NaN per contract), and use u64_to_str((uint64_t)ip, int_s) in JsonWriter_Float.

## 5. Suspicions

### IMG5-S1: Quantization Rounding Bias

**Severity:** S4 (minor numerical imprecision)

**Where:** `src/fm_jpeg.c:1080`, function `jpeg_write_block`

```c
v = (c < 0) ? -(int)((-c + (q >> 1)) / q) : (int)((c + (q >> 1)) / q);
```

**Belief:** The rounding formula `(c + q/2) / q` implements round-half-up, which has a slight bias toward positive values. The standard JPEG quantization is `round(c/q)`, which should use round-half-to-even (banker's rounding) for minimal bias. This could cause a systematic DC offset of ~0.5 quantization step across the image.

**Why not confirmed:** The effect is too small to measure in PSNR (would be < 0.01 dB). The library's encoder still produces output within 0.1 dB of libjpeg-turbo on average, suggesting any bias is negligible in practice.

**What stopped me:** Would require bit-exact comparison of quantized coefficients between this encoder and libjpeg at the same quality, which needs libjpeg headers (not available).

**Experiment to settle:** Build a test that extracts quantized DCT coefficients from both encoders and compares them coefficient-by-coefficient on a set of test images.

---

### IMG5-S2: Bilinear Scaling Edge Weight Calculation

**Severity:** S4 (minor numerical imprecision)

**Where:** `src/fm_image.c:1760-1770`, function `image_scale_run` (bilinear path)

```c
uint64_t vy = (((uint64_t)y * 2u + 1u) * sh * 128u) / dh;
uint64_t fy = (vy < 128u) ? 0u : (vy - 128u);
uint32_t y1 = (uint32_t)(fy / 256u);
uint32_t y2 = y1 + 1u;
uint32_t yw = (uint32_t)(fy & 255u);
```

**Belief:** The formula maps destination pixel centers to source pixel centers using `(y + 0.5) * sh / dh - 0.5`. The subtraction of 128 (0.5 in 1/256 units) and the clamp to 0 when `vy < 128` means the first destination row always samples from source row 0 with weight 0 for row 1. This is correct for the edge, but the transition from the edge to the interior could have a slight discontinuity in the weight function.

**Why not confirmed:** The existing tests pass, and visual inspection of scaled images shows no obvious artifacts. The effect would only be visible at extreme downscaling ratios (> 4:1) on images with sharp edges at the boundary.

**What stopped me:** Would require generating test images with known edge patterns and comparing the scaled output pixel-by-pixel with a reference implementation (Pillow BILINEAR with `reducing_gap=1`).

**Experiment to settle:** Create a 1000×1000 image with a sharp vertical edge at x=0, scale it to 100×100 with bilinear, and compare the first 5 columns with Pillow's output.

**Reach:** هر برنامهیی که طبق هدر، `SimpleVideo_AudioDataRead(pcm, N, &got)` را برای صدای ویدیو صدا بزند و ترک مونو باشد. با I2S خاموش (`SIMPLE_VIDEO_I2S=0`) این تنها راه گرفتن صدا است (خود هدر همین را میگوید)، و با `FM_AUDIO_OUT_CALLBACK` هم میشود صدا را از این راه برداشت. نتیجه برای فراخوان: نصف بافر نوشته میشود ولی `got` دو برابر تعداد واقعی است، و داده L/R درهم نیست بلکه نمونههای مونوی پشتسرهم است؛ پخش آن بهصورت استریو، صدا را با سرعت دوبرابر و با تقسیم کانال غلط پخش میکند و نیمهی دوم بافر (که فراخوان فکر میکند معتبر است) دستنخورده میماند.

### VID5-02 — `make` هدرهای `src/` را پیشنیاز نمیداند: `make test` میتواند کتابخانهی کهنه را سبز کند

## 9. بررسیشده و سالم (با عدد)

1. **قرارداد `Video_ReadAudioFrame`** — ۳۹ فایل ساختهشده × ۱۱ اندازهی بافر (`2, 4, 6, 8, 16, 64, 1000, 4608, 8192, 18432, 65536`). هر کدک دقیقاً همانجا که هدر میگوید قبول/رد میکند: PCM s16 از ظرفیت ۲ به بالا کامل و بایتبهبایت؛ PCM ۲۴/۳۲ بیتی از ۴ به بالا؛ G.711 از ۴۶۰۸ (نیاز به ۲×بسته)؛ MP3 از ۴۶۰۸؛ ADPCM و FLAC یک بستهی کامل؛ AAC گذر ADTS (۷۷۷۵ قاب در برابر ۷۴۹۷۰ نمونهی ffmpeg — مستند)؛ Opus بدون decoder. هیچ موردی «کمتر از مرجع بدون ردکردن» نداشت.
2. **تفاضلی محتوا**: PCM (s8/u8/s16/s24/s32/f32)، G.711 A/µ، ADPCM IMA/MS و FLAC **بایتبهبایت** با ffmpeg یکسان؛ MP3 و Vorbis حداکثر **۱ LSB** و همان طول.

4. **فازینگ**: ۶۰٬۰۰۰ و بعد ۳۹۳٬۸۰۰ اجرا زیر ASan+UBSan: `open_ok=248145 frames=507725 audio=993115`، بدون گزارش سنیتایزر، بدون توقف (watchdog ۲ ثانیه؛ با ۲۰۰ ms پنج HANG کاذب دیده شد و رد شد).

6. **۳۲بیتی**: `OK 32-bit plain (zig cc 0.17.1, x86-linux-musl): Results: 590/590 passed, 0 failures`.
7. **RAM استاتیک**: `g_video` = ۵۴۷٬۱۰۴ بایت (`FM_VIDEO_MAX_FRAMES=4096`، پیشفرض)، ۱٬۰۷۱٬۳۹۲ بایت (HUGE/8192)، ۱۵۳٬۸۸۸ بایت (SMALL/1024) — با README همخوان است.

## 13. دور بعد کجا را نگاه کند

1. **عمق پشته روی ARM با تفکیک تابع** — بزرگترین قابهای دیدهشده ۱۵٬۶۲۴ و ۱۵٬۵۷۰ بایت بودند که باید به تابع نسبت داده شوند؛ روش: `-fstack-size-section` + جدول نماد بخشها یا `-fstack-usage` با یک ابزار کوچک. احتمال یافته: متوسط، اثر: بالا (پشتهی MCU چند کیلوبایت است).
2. **حذف فایل کش در حال پخش روی FatFS** (S-3) — روش: شبیهسازی FatFS یا آزمون روی برد با کش کوچک و دو فایل بزرگ.
3. **مسیر G.711 و تخصیص پیش از بررسی ظرفیت** (S-1) — روش: فایل AVI با بستهی چندمگابایتی و هپ محدود (`FM_VIDEO_AUDIO_HEAP_MAX=65536`).
4. **VFR و `fps_num`/`fps_den`** — روش: ساخت MP4 چند `stts` و MKV بدون `DefaultDuration` و مقایسه با `ffprobe`.
5. **`SimpleVideo_Info` بیرون از پخش** (S-2) — روش: آزمون در `saveexamplestest` و تصمیم مستندسازی.

**برآورد:** با توجه به اینکه ظرفها و مسیر صدا دو دور زیر ASan و تفاضلی بودهاند و ۱۶ جهش گرفته میشود، احتمال یافتن S1 تازه در همین بخش **کم** است؛ محتملترین جای S2 تازه، سمت پخش پخشکننده است (حالتهایی که آزمون میزبان بازیشان نمیکند: تغییر حالت صدا در میانهی پخش، پلیلیست با فایلهای همنام، و رفتار `SetSwap16` هنگام تغییر اندازه).

```python
# sweep.py -- every vector, every buffer size: how many samples come out
import subprocess, glob, os, numpy as np
FF = ".../imageio_ffmpeg/binaries/ffmpeg-linux-x86_64-v9.0.2"
PROBE = "./va_probe"            # Video_Open + Video_ReadAudioFrame loop -> raw s16le
CAPS = [2, 4, 6, 8, 16, 64, 1000, 4608, 8192, 18432, 65536]
for path in sorted(glob.glob("files/*")):
    ref = subprocess.run([FF, "-loglevel", "error", "-i", path, "-map", "0:a:0",
                          "-f", "s16le", "-"], capture_output=True).stdout
    out = [os.path.basename(path), "ref=%d" % (len(ref) // 2)]
    for c in CAPS:
        subprocess.run([PROBE, path, "--cap", str(c), "--audio-out", "/tmp/s.pcm"],
                       capture_output=True)
        got = os.path.getsize("/tmp/s.pcm") // 2 if os.path.exists("/tmp/s.pcm") else 0
        os.remove("/tmp/s.pcm") if os.path.exists("/tmp/s.pcm") else None
        out.append("%d:%d" % (c, got))
    print(" ".join(out))
```

## 4. Confirmed findings

### SAV3-01 — the flags-stamp check passes while the objects of one rule link stale code

**Severity** S4 (a test that cannot fail: it exists to hold SAVE1-F6 and it does not).

**Where** `tools/check_flag_stamp.sh:36-38`, and the rule it is supposed to watch, `Makefile:299`:

```sh
uptodate libfilemanager.a || fail "same flags: make wants to rebuild"
uptodate libfilemanager.a CFLAGS_EXTRA=-DFM_STAMP_PROBE=1 &&
    fail "a new -D did not make the objects out of date"
```
```make
src/%.o: src/%.c include/fm*.h $(FLAGS_STAMP)
```
(`uptodate()` is `$MAKE -s -q "$@"`; `make -q` prints nothing and answers by exit status.)

**Reach** `make check` runs `sh tools/check_flag_stamp.sh`; the maintainers run it by hand after touching the build rules, which is exactly the situation the script is for. Nothing in the library's runtime is involved: the defect is a person believing `check_flag_stamp: OK`.

**How to reproduce** (from a clean checkout of `fc31b25`)

```sh
cp -a Clain_FileManager/FileManager_lib /tmp/m9 && cd /tmp/m9
# the mutation: one rule loses its stamp prerequisite
python3 - <<'EOF'
p='Makefile'; s=open(p,'rb').read().decode()
old='src/%.o: src/%.c include/fm*.h $(FLAGS_STAMP)\r\n'
assert s.count(old)==1
open(p,'wb').write(s.replace(old,'src/%.o: src/%.c include/fm*.h\r\n').encode())
EOF
sh tools/check_flag_stamp.sh ; echo "exit=$?"
```
Printed (verbatim, the whole output):

```
check_flag_stamp: OK
exit=0
```

With the fix of this finding applied to the same mutated tree:

```
FAIL flag stamp: a new -D did not make src/fm_core.o out of date
FAIL flag stamp: a new -D did not make src/fm_audio_enc.o out of date
FAIL flag stamp: a new -D did not make src/fm_video_enc.o out of date
exit=1
```
and on the *unmutated* tree the fixed script prints `check_flag_stamp: OK`, `exit=0`.

**Expected and observed** Expected: the check notices that the objects of a rule no longer depend on the flags stamp, i.e. that `make FM_USE_JSON=0` after `make` would relink stale objects (the SAVE1-F6 bug). Observed: it prints `OK` and exits 0, while `src/*.o` are indeed stale: `libfilemanager.a` is out of date only because its *own* rule names `$(FLAGS_STAMP)`, so `make -q libfilemanager.a` answers "out of date" and `make` then relinks the archive from objects that were never recompiled with the new `-D`. The user's build mixes two flag sets, which is the defect SAVE1-F6 was about.

**Root cause** The check asks the *aggregate* (`libfilemanager.a`) instead of the *parts* (`src/*.o`). The archive's prerequisite list carries the stamp independently of the object rules, so the predicate "the archive is out of date" stays true even when the objects are not. One `make -q` of one object per rule distinguishes the two; the archive does not.

**Proposed fix**

```diff
diff --git a/tools/check_flag_stamp.sh b/tools/check_flag_stamp.sh
index 755b36c..0c8d405 100644
--- a/tools/check_flag_stamp.sh
+++ b/tools/check_flag_stamp.sh
@@ -36,6 +36,14 @@ $MAKE -s -j4 libfilemanager.a >/dev/null 2>&1 || { echo "FAIL flag stamp: build"
 uptodate libfilemanager.a || fail "same flags: make wants to rebuild"
 uptodate libfilemanager.a CFLAGS_EXTRA=-DFM_STAMP_PROBE=1 &&
     fail "a new -D did not make the objects out of date"
+# The archive can be out of date on its own account (its rule names the
+# stamp too), so that check passes while the objects link stale code: ask
+# the objects of every rule, not the archive.
+for o in src/fm_core.o src/fm_audio_enc.o src/fm_video_enc.o \
+         backends/fm_posix_fs.o backends/fm_ramdisk.o; do
+    uptodate "$o" CFLAGS_EXTRA=-DFM_STAMP_PROBE=1 &&
+        fail "a new -D did not make $o out of date"
+done
 uptodate libfilemanager.a &&
     fail "going back to the first flags did not make them out of date"
 $MAKE -s -j4 libfilemanager.a >/dev/null 2>&1 || fail "rebuild"
```

Applied: **yes** (in `/home/user/fs1`, a copy of `fc31b25`). After the fix: the mutated tree gives the three `FAIL` lines above and `exit=1`; the clean tree gives `check_flag_stamp: OK` and `exit=0` (the whole script, 36 s, on a tree with no objects). `make test` is untouched by this change (the script is not part of it and no library source changes); the whole `make check` was not re-run. Note the one-file-per-rule choice: `src/`, `backends/` and the three `third_party/` rules are the five object rules of the `Makefile`; one object of each is enough to see a missing prerequisite, and a complete list would go stale as files are added.

**Regression test** The script *is* the test; the loop above is the added check. On `fc31b25` it fails (the mutation is invisible), with the fix it passes (the mutation is reported). The three `fail` lines are the assertion.

**Siblings** The same "ask the aggregate" shape in `tools/`: `check_switch_names.sh` builds a scratch program per case and is not affected; `check_32bit.sh` compares a whole run. Nothing else.

**Since** `48a00bc` (the commit that introduced the script for SAVE1-F6): the SAVE1-F6 rewrite of `Makefile` added `$(FLAGS_STAMP)` to *six* rules; `git show 48a00bc -- tools/check_flag_stamp.sh` shows the archive-only check from the first version, and it was never widened.

## 5. Suspicions

### SAV3-04 — a card write inside the I2S half refill can starve the next half

**What I believe** With `SimpleAudio_RecPlaying` active (the board's `arec` / `arecs`), the sound recorder writes to the file from `simple_audio_rec_tap`, which `AudioDma` calls from the *refill path* of the half that is about to be played: `top_api/audio_dma_player.h:364` (`if (state->save_fn != NULL && filled > prev)`) inside `audio_dma_fill_half` (`:267`). On the board that path is entered from `SimpleAudio_Poll`, and `SimpleAudio_Poll` is what `simple_audio_idle` (`top_api/simple_audio.h:505`) runs — the function `FM_SetIdle` installs at `:734`, i.e. **`FM_Idle()`, which the library's own picture and video decoders call in the middle of their work** (`src/fm_jpeg.c:358` and `:512`, `src/fm_png.c:1233`, `src/fm_image.c:642/669/1339/1697/1740/1772`, `src/fm_video.c:5043/5141/5401`, `src/fm_h264.c:678`). So on a board that decodes a JPEG while music is being recorded, a card write happens inside the refill window of the half the DMA is waiting for. With a card whose write takes "several hundred ms" (the prompt's own figure) and `SIMPLE_VIDEO_HALF_SAMPLES`-sized halves of 0.5–0.7 s, the refill can miss its deadline; `AudioDma_Poll` then reports an underrun and stops the player, and the recording ends in the middle. The library's own example layer avoids exactly this: `SaveDemo_MusicCallback` copies into a RAM ring and writes from the main loop, and the `FM_AudioDataFn` comment forbids file I/O in the callback.

**What I measured** `a3_idle_probe.c` installs a counting wrapper on the POSIX adapter's `file_write`, starts `RecPlaying("/rec")`, plays one 5 s track and raises eight half/full interrupts, calling `FM_Idle()` with the counter up:

```
--- calling FM_Idle() the way a JPEG decode does ---
file_write calls inside FM_Idle: 24 (256208 bytes), outside: 0
RESULT: the recorder WROTE TO THE FILE INSIDE FM_Idle
```
So the nesting is a fact, not a reading. What I could not show is the *consequence*: a PC write to a tmpfs takes microseconds, and I have no board and no card model. Delaying the write inside my wrapper would only measure my own delay; it would not show what this library does about a late refill on hardware.

**What stopped me** No board, no SD card, no cycle-accurate model of the I2S half period, and the prompt's "nothing has run on hardware" limit applies to every timing claim. Also relevant: with `RecPlaying` the tap is called only when `sa_rec.playing` is set, so this needs a *recording of the playing music* (or `SimpleAudio_Convert`, whose progress callback calls `simple_audio_idle()` as well, `simple_audio.h:2282`) — the plain `RecStart` + `RecWrite` path does not do it (measured, 9.6).

**The experiment that would settle it** On the board, with `arec` running and a slideshow decoding large JPEGs, log `sa.dma.starve` / the underrun counter; or in the host test, put a `File_Flush` plus a simulated 3 ms delay per 4 KB into the adapter while the test's virtual clock advances at 44.1 kHz and see whether `AudioDma_Poll` reports an underrun before the track ends. The pseudo-hardware test of `tools/save_examples_host_test.c` already has a controllable clock (`sim_step_ms`) and could host it.

### 9.2 IMA ADPCM: length, `fact`, padding and error against ffmpeg's own encoder

`a3_adpcm.c` writes 5 000 and 9 000 frames as IMA ADPCM through `AudioFileWriter`, parses the header itself and reads the file back with `Audio_Read`; PyAV then decodes the same files. Measured: `block_align 256`, `samples/block 505`, `fact` = the number of frames written (5 000 / 9 000), `data` = whole blocks (2 560 / 4 608 bytes), the reader returns 5 050 / 9 090 frames — the whole blocks — and libav returns exactly the same 5 050 / 9 090. The padded tail is the decoder's continuation (50 / 90 non-zero frames), not silence: an unavoidable property of IMA framing, ≤ 3.2 ms, and identical in ffmpeg's decoder. Error against the input over the overlap: **159** for a 300 Hz full-scale sine (ffmpeg's own `adpcm_ima_wav` on the same signal: **4 681**), **19 721** for a full-scale 200-sample sawtooth (ffmpeg: **19 614**) — the library's encoder is at least as good as the reference; the large figure is what the format does on a step, not a defect. My earlier session note of "5000→5050, 9000→10205" was produced with a harness bug (a frame counter carried across two files, `total` not reset per pass); the corrected figures are the ones above.

### 9.4 Where the recorder's file writes really happen

`a3_idle_probe.c`: `RecPlaying("/rec")` + a 5 s track + 8 raised half/full interrupts + `FM_Idle()` with a counting wrapper on the adapter's `file_write`: **24 writes / 256 208 bytes inside `FM_Idle`, 0 outside**. The chain `FM_SetIdle` (`src/fm_core.c:187`) ← `SimpleIdle_Add(simple_audio_idle)` (`top_api/simple_audio.h:734`) ← `simple_idle_dispatch` (`top_api/simple_idle_mux.h`) ← `SimpleAudio_Poll` ← `AudioDma_Poll` ← `audio_dma_fill_half` (`top_api/audio_dma_player.h:267`) ← `state->save_fn` (`:364`, set at `:733` / `AudioDma_SetSaveCallback` `:818`) ← `simple_audio_rec_tap` (`top_api/simple_audio.h:2074`) is as I describe it, and `FM_Idle` itself is re-entrancy safe (one hook run at a time, `src/fm_core.c:194-210`). The IRQ hooks (`AudioDma_HalfCallback`/`FullCallback`, `:1001`/`:1014`) only set flags, as the header says. Whether the nesting hurts is SAV3-04 (suspicion).

### 9.5 What is on the card after a "reset"

`a3_abandon.c` writes and `_exit()`s (no `Close`); `ab.avi` is 399 594 B with 13 318 B still in the writer's buffer:

| File | On the card | Header says | libav |
|---|---|---|---|
| `ab_wav.wav` | 409 600 B | `data` 262 100 (the last checkpoint) | 65 525 frames (= 262 100 / 4) |
| `ab_adpcm.wav` | 98 304 B (below one checkpoint) | `data` 0, `fact` 0 | 97 904 frames |

The AVI is exactly the documented case ("valid without an index, this library opens it"); its picture and sound counts agree (129 × 640 = 82 560). The two audio cases are SAV3-02.

### 9.6 The two recorders of `SimpleAudio` do not interfere

`a3_two_rec.c`: `RecStart("/rec/mic.wav", 16000, 1)` + four `RecWrite` of a marked block, then the music starts and plays eight halves, then `RecWrite` again, then `RecStop`. Output: `RecActive = 1` throughout, `/rec/mic.wav` = `WAV 16000 Hz 1 ch, 4000 frames`, and all 4 000 samples are the mark (`0 are music`). The reason is `simple_audio_rec_tap`'s first line (`top_api/simple_audio.h:2081`, `if (!sa_rec.playing …) return;` — `playing` is only set by `RecPlaying`, `:2232`), and `RecStart` refuses while either is active (`:2206`); `RecWrite` returns `FM_ERR_BUSY` while `RecPlaying` is active (`:1859`). The one writer is shared but the states exclude each other. Job 4 item 5's question ("do they share the one writer, and what happens") answer: they share `sa_rec.w`, and nothing happens.

### 9.7 A long `RecPlaying` session

`a3_rec_grow.c`: 24 halves of a 0.75 s track on `REPEAT_ALL`, single-file mode, the size read with the host's `stat()`: 32 768 → 81 920 → … → 573 440, `RecStop = 0`, final 576 044 B = 44 + 144 000 stereo frames. Monotone, no re-open, no truncation, the recorder's own `frames` counter agrees with the file at every step.

## 13. Where the next round should look

1. **The card write inside the I2S refill (SAV3-04).** Reason: it is the only place where a *slow card* and *sound* meet, and it is the one thing this part has never measured on a card. Build (from `Clain_FileManager/FileManager_lib`, after `make libfilemanager.a`):

The mount is the POSIX adapter at `/`, i.e. the process's working directory, so the paths below
are created under the directory the program is started from. Full source:

```c
/* a3_abandon.c -- audit helper (local only): write a file with a writer of the
 * library and _exit() without closing it, the way a reset / power cut does.
 * Then the file on the card is judged by libav (and by VideoFile_Repair). */
#include "file_manager.h"
#include "fm_audio.h"
#include "fm_video.h"
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/stat.h>

extern FM_Result PosixFS_Init(FM_FS *fs);

static int16_t pcm[4410 * 2];

static void fill(size_t n, uint16_t ch, uint32_t *seed)
{
    size_t i;

    for (i = 0; i < n * ch; i++)
    {
        *seed = *seed * 1664525u + 1013904223u;
        pcm[i] = (int16_t)((*seed >> 16) & 0x7FFF);
    }
}

int main(int argc, char **argv)
{
    FM_FS fs;
    const char *mode = (argc > 1) ? argv[1] : "wav";
    const char *path = (argc > 2) ? argv[2] : "/tmp/a3/ab.wav";
    uint32_t rate = (argc > 3) ? (uint32_t)atoi(argv[3]) : 44100;
    uint16_t ch = (argc > 4) ? (uint16_t)atoi(argv[4]) : 2;
    uint32_t kb = (argc > 5) ? (uint32_t)atoi(argv[5]) : 400;
    uint32_t seed = 7u;

    if (FileManager_Init() != FM_OK || PosixFS_Init(&fs) != FM_OK ||
        FS_Mount("/", &fs) != FM_OK)
    {
        printf("FATAL fs\n");
        return 1;
    }
    if (strcmp(mode, "avi") == 0)
    {
        FM_VideoFileWriter vw;
        FM_VideoSaveConfig sc;
        uint8_t *rgb;
        uint16_t w = 160, h = 120;
        uint32_t written = 0;
        uint32_t n = 0;
        FM_Result r;

        memset(&sc, 0, sizeof(sc));
        sc.width = w; sc.height = h; sc.fps = 25; sc.quality = 80;
        sc.audio_rate = 16000; sc.audio_channels = 1;
        rgb = (uint8_t *)malloc((size_t)w * h * 3u);
        r = VideoFileWriter_Open(&vw, path, &sc);
        if (r != FM_OK) { printf("open r=%d\n", (int)r); return 1; }
        while (written < kb * 1024u)
        {
            uint32_t x, y;
            for (y = 0; y < h; y++)
            {
                for (x = 0; x < w; x++)
                {
                    uint8_t *p = rgb + 3u * ((size_t)y * w + x);
                    p[0] = (uint8_t)(x + n); p[1] = (uint8_t)y; p[2] = (uint8_t)(x ^ y);
                }
            }
            r = VideoFileWriter_WriteFrame(&vw, rgb, FM_PIXEL_RGB888);
            if (r != FM_OK) { printf("frame r=%d at %lu\n", (int)r, (unsigned long)vw.frames); break; }
            fill(640, 1, &seed);
            r = VideoFileWriter_WriteAudio(&vw, pcm, 640);
            if (r != FM_OK) { printf("audio r=%d\n", (int)r); break; }
            written = (uint32_t)(vw.buf_pos + vw.buf_len);
            n++;
            if (n > 20000u) break;
        }
        printf("avi: %lu frames, %lu bytes on the card (buffered %lu)\n",
               (unsigned long)vw.frames, (unsigned long)vw.buf_pos,
               (unsigned long)vw.buf_len);
        fflush(stdout);
        _exit(0);                     /* no Close: a reset */
    }
    else
    {
        FM_AudioFileWriter w;
        FM_AudioEncodeConfig c;
        FM_AudioFileFormat fmt = FM_AUDIO_FILE_WAV;
        uint32_t written = 0;
        FM_Result r;

        if (strcmp(mode, "adpcm") == 0) fmt = FM_AUDIO_FILE_ADPCM;
        if (strcmp(mode, "flac") == 0) fmt = FM_AUDIO_FILE_FLAC;
        memset(&c, 0, sizeof(c));
        c.sample_rate = rate;
        c.channels = ch;
        c.bits_per_sample = 16;
        r = AudioFileWriter_Open(&w, path, fmt, &c);
        if (r != FM_OK) { printf("open r=%d\n", (int)r); return 1; }
        while (written < kb * 1024u)
        {
            size_t n = 1102;
            size_t done = 0;
            fill(n, ch, &seed);
            r = AudioFileWriter_WriteFrames(&w, pcm, n, &done);
            if (r != FM_OK) { printf("write r=%d\n", (int)r); break; }
            written += (uint32_t)(done * ch * 2u);
        }
        printf("%s: %lu frames, %lu bytes written\n", mode,
               (unsigned long)w.frames, (unsigned long)written);
        fflush(stdout);
        _exit(0);                     /* no Close: a reset */
    }
    return 0;
}
```
